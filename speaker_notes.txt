========================================================
AEPLO JTAG ACCELERATOR FOR EMBEDDED PDLC AI OPTIMISATION
Speaker Notes - V7 / Honeywell Theme
14-slide presentation | target: ~5 minutes
========================================================

--------------------------------------------------------
SLIDE 1 - COVER  (~15 sec)
--------------------------------------------------------
"Today we are presenting the AEPLO JTAG Accelerator for
Embedded PDLC AI Optimisation. The story is simple: connect
planning data, code, AI assistance, and JTAG evidence so we
can move faster from discovery to validated launch readiness."

--------------------------------------------------------
SLIDE 2 - THE PROBLEM  (~20 sec)
--------------------------------------------------------
"Embedded PDLC data is fragmented. Jira, Confluence, GitHub,
QA results, and JTAG/SWD hardware evidence often sit in
separate places. That slows decisions across PG1, PG3, and PG5
and makes launch readiness harder to prove."

--------------------------------------------------------
SLIDE 3 - SOLUTION  (~20 sec)
--------------------------------------------------------
"AEPLO becomes the connected platform. It treats JTAG evidence
as a native PDLC signal, combines it with traceability and
project context, and applies AI optimisation through ROVO
Studio, Copilot, and specialised agents."

--------------------------------------------------------
SLIDE 4 - ARCHITECTURE  (~20 sec)
--------------------------------------------------------
"The architecture connects Jira, Confluence, GitHub, Copilot,
ROVO Studio, Atlassian MCP, and JTAG/SWD evidence. AEPLO then
turns that data into orchestration, controlled fixes, gate
verdicts, and reusable launch evidence."

--------------------------------------------------------
SLIDE 5 - CONNECTED PLATFORM STACK  (~20 sec)
--------------------------------------------------------
"This is the working tool stack. Jira and Confluence carry the
planning and knowledge base. GitHub and Copilot support code
change. Atlassian MCP and AEPLO orchestrate the workflow. The
JTAG Accelerator adds physical target evidence."

--------------------------------------------------------
SLIDE 6 - PG1 DISCOVERY  (~20 sec)
--------------------------------------------------------
"At PG1, AEPLO collects PRD context, Jira themes, Confluence
architecture, GitHub history, and target-board assumptions. It
maps PDLC risks and embedded debug hotspots, then produces a
risk-backed demo scope and validation plan."

--------------------------------------------------------
SLIDE 7 - PG3 DEVELOPMENT  (~22 sec)
--------------------------------------------------------
"At PG3, the JTAG Accelerator converts embedded coding defects
into hardware-backed root-cause analysis. It captures registers,
stack frames, memory evidence, and probe logs, then links the
controlled fix back to GitHub and Jira."

--------------------------------------------------------
SLIDE 8 - AGENT JTAG DEBUGGING: FROM FAILURE TO FIX  (~35 sec)
--------------------------------------------------------
"This slide shows three real-time use cases for the JTAG agent.
First, a bootloader-to-application handoff caused a HardFault
because SysTick was enabled but the application vector table had
no SysTick handler. The agent correlated the PC, vector table,
and peripheral state and reduced diagnosis from days to about
45 minutes.

Second, the agent emulated a sub-zero ADC condition at room
temperature. That allowed driver reinitialisation and gain
adjustment to be validated without waiting for thermal chamber
cycling.

Third, for a boot failure after flashing a new build, the agent
traced the Program Counter and identified execution going to
system ROM instead of internal flash. The key message is that
JTAG evidence becomes actionable AI context, not just a debug
artifact."

--------------------------------------------------------
SLIDE 9 - PG5 VALIDATION GATEKEEPER  (~20 sec)
--------------------------------------------------------
"At PG5, AEPLO evaluates code, QA results, traceability, and
JTAG/SWD evidence together. The gatekeeper produces a clear
READY or NOT_READY verdict, plus a prioritized remediation list
for validation and launch preparation."

--------------------------------------------------------
SLIDE 10 - QA2RELEASE INTELLIGENCE  (~20 sec)
--------------------------------------------------------
"QA2Release closes the loop. Test failures and JTAG evidence
feed root-cause analysis, test optimisation, and next-release
learning. The output becomes Jira actions, Confluence summaries,
and better evidence for the next gate."

--------------------------------------------------------
SLIDE 11 - DEMO FLOW  (~22 sec)
--------------------------------------------------------
"The live demo follows three stages: PG1 discovery in ROVO
Studio, PG3 development with the JTAG Accelerator and Copilot,
and PG5 validation with AEPLO release gating and automated
launch-prep evidence."

--------------------------------------------------------
SLIDE 12 - BUSINESS OUTCOMES  (~22 sec)
--------------------------------------------------------
"The value for embedded teams is practical: reduced defect
leakage, faster firmware root cause, clearer NPI gate
confidence, and AI-optimised PDLC work across planning, coding,
validation, and launch preparation."

--------------------------------------------------------
SLIDE 13 - EVALUATION MATRIX  (~25 sec)
--------------------------------------------------------
"The matrix connects the demo to measurable judging criteria.
We show a 41 percent lead-time drop, 60 percent fewer projected
defect escapes, 85 percent BA hosting readiness, and measurable
agentic AI execution metrics including handoff success, tool
calling accuracy, and prompt caching utilisation."

--------------------------------------------------------
SLIDE 14 - CONCLUSION  (~18 sec)
--------------------------------------------------------
"The common idea is connected embedded data plus intelligent
PDLC action. AEPLO, with the JTAG Accelerator inside it, helps
optimise every gate from PG1 to PG5. Thank you."
